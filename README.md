# robot_arm

Arduino Mega 2560용 평행링크 로봇팔입니다. X/Y 모터를 함께 구동하는
상대 직선 이동(mm)을 지원하며, Z 베이스는 기존 각도 명령을 사용합니다.

## 파일과 업로드

GitHub의 **Code → Download ZIP**으로 받거나 저장소를 clone하세요.
`robot_arm.ino`, `xy_control.h`, `xy_motion.h`, `z_homing.h`를 같은 `robot_arm` 폴더에 둡니다.
`.ino`만 복사하면 새 기능이 컴파일되지 않습니다.

Arduino IDE에서 보드는 **Arduino Mega or Mega 2560**, 프로세서는
**ATmega2560**을 선택합니다. 기존 `Wire` 및 `Servo` 라이브러리를 사용합니다.
시리얼 모니터는 **9600bps, 줄바꿈 전송**입니다.

## 기존 명령

| 명령 | 의미 |
| --- | --- |
| `x 1`, `y 1` | 해당 모터의 관절 출력각을 1도 상대 이동 |
| `z 10` | 베이스를 10도 상대 회전 |
| `e` | 기존 X/Y/Z 엔코더 출력 |
| `zero` | 기존 엔코더 카운터를 0으로 초기화 |
| `h` | D22/D23/D24 홈 스위치 상태 출력 |
| `homez` | Z 음수 방향으로 2단계 자동 호밍, 성공 시 Z만 영점 설정 |
| `o` / `open` | D10 그리퍼 100도 |
| `c` / `close` | 그리퍼 20도 |
| `angle 60` | 그리퍼를 지정 각도로 이동 |

기존 모터/엔코더 핀과 함수 본문은 유지했습니다. X/Y/Z 모두 실물에서
확인된 모터 9T → 출력 32T 기어비를 사용합니다. AS5600은 Z 모터축을 측정하며
출력각은 모터축 각도를 `32/9`로 나눕니다. 전원 ON/리셋 시 그리퍼는 기존처럼
100도 열림 명령을 받습니다.

## X/Y mm 명령

| 명령 | 의미 |
| --- | --- |
| `xyhelp` | 기준 등록 방법과 명령 안내 |
| `xycal A B SX SY` | 현재 실측 링크 각도와 방향 등록, 모터 이동 없음 |
| `pos` | 엔코더에서 계산한 링크 각도와 손목 관절 위치 |
| `xycheck 1 0` | 앞으로 1mm 이동의 펄스 수 미리 보기, 모터 이동 없음 |
| `xm 1` / `xm -1` | 끝단을 앞으로 / 뒤로 1mm |
| `ym 1` / `ym -1` | 끝단을 위로 / 아래로 1mm |
| `xy 1 1` | 앞으로 1mm, 위로 1mm인 목표점까지 직선 이동 |
| `!` | mm 이동 중 수신되면 X/Y 펄스 중단, 기준 등록 해제 |

`x`, `y`는 계속 **도 단위**입니다. mm 명령에는 `xm`, `ym`, `xy`를 사용합니다.
앞/뒤는 현재 베이스가 향한 팔의 수직 평면에서의 방향입니다. Z를 회전하면
이 평면도 회전하며, 책상에 고정된 전역 X/Y 좌표 명령은 아닙니다.

새 핀은 없습니다. Z 홈 스위치는 기존 D24를 사용하며 아래의 Z 호밍 절차를 지원합니다.
X/Y 스위치는 `h`로 확인하는 기능만 있으며, X/Y 자동 호밍·리밋 정지는 아직 없습니다.

## Z 호밍 시험

확인된 접근 방향은 **음수(-)**, 후퇴 방향은 **양수(+)**입니다.
Z 스위치는 COM → GND, NC → D24, `INPUT_PULLUP`입니다.
놓으면 LOW, 누르거나 배선이 끊기면 HIGH이며 기존 배선을 바꿀 필요는 없습니다.

1. `h`로 놓으면 LOW / 누르면 HIGH인지 먼저 확인합니다.
2. 팔·그리퍼가 회전할 공간을 확보하고 스위치에서 가까운 위치에서 시작합니다.
3. 시리얼 모니터 9600bps, 새 줄 설정으로 `homez`를 전송합니다.
4. 처음부터 HIGH이면 양수 방향으로 최대 5도 이내에서 LOW를 찾고 1도 더 후퇴합니다.
5. 음수 방향으로 최대 30도 탐색하고 HIGH 감지 즉시 펄스를 중단합니다.
6. 양수 방향으로 LOW를 찾은 뒤 1도 더 후퇴하고, 절반 속도로 음수 재접근합니다.
7. 두 번째 HIGH가 안정적으로 유지되고 AS5600 읽기가 성공하면 Z 카운터만 0으로 설정합니다.
8. `e`로 Z가 약 0도인지 확인하고 `z 1`로 빠져나온 뒤 `h`에서 LOW인지 확인합니다.

모든 각도 제한은 기어비를 적용한 **베이스 출력축 기준**입니다.
탐색 펄스 HIGH/LOW는 각각 4000µs, 마지막 재접근은 각각 8000µs로 설정했습니다.
처음 감지한 순간 멈춘 뒤 20ms 동안 접점을 확인하며, 바운스가 있으면 오류로 중단합니다.
전체 호밍은 20초 이내여야 하고 마지막 재접근은 최대 7도입니다.
`homez`는 전원 ON 시 자동 실행하지 않습니다. 기존처럼 시작 시 그리퍼는 100도로 열립니다.

정상 출력 순서는 다음과 같습니다. 처음 눌린 상태라면 SEEK 전에 RELEASE가 한 번 더 나옵니다.

```text
Z HOME: START; ! stops; search max 30 DEG; total timeout 20 s
Z HOME: SEEK -
Z HOME: RELEASE + (max 5 DEG), then clearance +1 DEG
Z HOME: SLOW SEEK -
Z HOME DONE: Z=0 DEG; switch HIGH; move z positive to leave home
```

호밍 중 `!`를 전송하면 펄스를 중단합니다. 다른 입력은 호밍 중 버립니다.
스위치를 못 찾거나 해제하지 못한 경우, 접점 불안정, AS5600 통신 실패, 시간 초과,
사용자 중단이면 `Z HOME ERROR: stopped; zero NOT set`을 출력하며 영점을 설정하지 않습니다.
이때는 이전 영점을 새 홈으로 믿고 진행하지 말고 원인을 해결한 뒤 호밍을 다시 실행합니다.
스위치를 못 찾으면 배선·접근 방향·시작 거리를 확인하고, 해제가 안 되면 NC 접점과
기계적 눌림을 확인하세요. I²C 통신은 지원되는 Wire에서 25ms 타임아웃을 적용했습니다.

일반 `z` 음수 이동도 매 펄스 전에 D24를 검사하여 HIGH이면
`Z HOME LIMIT: negative motion stopped`를 출력하고 중단합니다.
양수 후퇴는 허용합니다. 이 기능은 **홈 쪽 한 방향의 리밋**이며 반대쪽 회전 한계는
아직 정해지지 않았습니다. `!` 정지는 `homez`와 mm 이동에서만 처리합니다.
펄스 중단은 모터 전원이나 유지 토크를 끄는 동작이 아닙니다.

## 먼저 현재 자세 등록

전원 재인가 때마다 측정한 자세를 등록해야 mm 이동을 허용합니다.
등록값은 EEPROM에 저장하지 않습니다. 실제 자세를 모르는 상태에서 임의의
각도를 넣으면 계산이 틀려집니다. `zero`는 기구학적 각도를 알아내는 명령이 아닙니다.

- `A`: 베이스 쪽 주 관절 중심에서 중간 관절 중심으로 향하는 첫 링크의 **절대각**.
  Y 모터에 대응합니다.
- `B`: 중간 관절 중심에서 끝단 손목 관절 중심으로 향하는 둘째 링크의 **절대각**.
  X 모터에 대응합니다. 두 링크 사이의 상대각이 아닙니다.
- 두 각도 모두 앞쪽 수평을 0도, 위쪽 수직을 +90도, 뒤쪽 수평을 ±180도로
  정의합니다. 아래쪽을 향하는 링크는 음의 각도로 표현할 수 있습니다.
- `SX`: 기존 `x` 양수 명령으로 B가 증가하면 `1`, 감소하면 `-1`.
- `SY`: 기존 `y` 양수 명령으로 A가 증가하면 `1`, 감소하면 `-1`.

실제 자세를 측정한 뒤 `xycal A B SX SY`의 네 문자를 해당 숫자로 바꿔 전송합니다.
예를 들어 **실제로** A=60도, B=-30도이고 두 양수 명령이 각도를 증가시키는 경우에만
`xycal 60 -30 1 1`입니다. 이 숫자는 이 로봇의 홈 각도로 확정한 값이 아닙니다.
각도가 어떻게 대응하는지 확인한 뒤에는 다시 현재 자세를 측정하고 등록하세요.

등록 시 기존 X/Y 엔코더를 0으로 지우지 않고 그 순간 카운트를 기준으로 보관합니다.
`x`, `y`, `zero`, 정지 또는 추종 오차 발생 후에는 기준을 다시 등록해야 합니다.
`z`, 그리퍼, `h`, `e` 명령은 기준을 해제하지 않습니다.

X/Y 홈 스위치 설치 후에는 홈 자세에서의 실제 A/B와 접근 방향, 허용 관절 범위를
확정하고 자동 등록·리밋 기능을 연결해야 합니다. 기구학상 수평 0도와 홈 카운터 0은
다른 기준입니다.

## 기구학 및 움직임

원본과 동일한 두 주요 링크의 관절 중심 간 길이 120mm를 사용합니다.
기존 프로젝트 식의 `theta1`이 A이고, B는 `theta2 - 180도`와 같은 방향입니다.

```text
손목 앞뒤 위치 = 120 cos(A) + 120 cos(B)
손목 높이     = 120 sin(A) + 120 sin(B)
```

내부 삼각함수는 radian으로 계산합니다. 역기구학은 현재 조립 분기와 가까운
각도 해를 유지하며, 목표 경로를 먼저 검사한 뒤 0.5mm 이하 구간으로 나눕니다.
각 구간의 두 모터 펄스는 DDA 방식으로 같은 시간 안에 분배합니다. 구간마다
반올림 오차가 쌓이지 않도록 명령 시작점 기준 누적 펄스를 계산합니다.

그리퍼 방향과 장착 오프셋이 이동 중 일정하면 손목과 잡는 중심의 상대 변위는 같습니다.
`pos`는 **베이스 주 관절 기준 손목 위치**이며 건전지 중심이나 책상 높이가 아닙니다.
다리 36 → 60mm 변경과 그리퍼 오프셋은 고정된 평행이동이므로 상대 mm 이동량에는
영향이 없습니다. 건전지의 절대 좌표로 접근할 때는 해당 오프셋을 별도로 반영해야 합니다.

## 첫 시험 범위와 정지

- 한 명령의 직선 거리 최대 10mm, 각 링크 변화 최대 5도.
- 등록한 자세에서 각 링크가 ±15도를 벗어나는 경로는 거부합니다.
  이 범위는 초기 시험용이며, 실물의 충돌 없는 범위로 검증된 값은 아닙니다.
- 두 링크가 일직선으로 펴지거나 접히는 자세의 10도 이내를 피합니다.
- mm 이동 목표 속도 최대 2mm/s, 낮은 가감속을 사용합니다. 실제 속도는
  펄스 간격 제한, 인터럽트, I²C 읽기 등의 영향으로 더 느릴 수 있습니다.
- 구간마다 X/Y 엔코더와 누적 명령각을 비교합니다. 이동 중 1도, 종료 후
  200ms 대기한 시점에 0.15도를 넘는 추종 오차가 있으면 중단·기준 해제합니다.
- mm 이동 중에는 시리얼 `!`만 처리하고 다른 입력은 버립니다. `!`는 기존
  `x/y/z` 각도 이동을 중단시키는 기능은 아닙니다.
- 펄스 중단은 드라이버 전원이나 모터 유지 토크를 끄지 않습니다.

펄스 분해능·기구 오차 때문에 실제 직선은 근사 경로입니다. 엔코더 결과 역시
모터축을 기준으로 계산하므로 기어 백래시, 링크 휨, 그리퍼 미끄러짐을 직접
측정하지 못합니다. 자동 재시도나 오차를 따라 추가로 움직이는 보정은 하지 않습니다.

## 실제 시험 순서와 예상 출력

1. 건전지를 빼고 여유 있는 자세에서 기존 `x 1`, `y 1`로 링크 대응과 방향을 확인합니다.
2. 현재 A/B를 측정해 `xycal`로 등록합니다.
3. `xycheck 1 0`으로 계산 결과를 확인합니다. 이때는 움직이지 않습니다.
4. `xm 1`을 실행하고 앞뒤 변위와 높이 유지 여부를 측정합니다.
5. `xm -1`, `ym 1`, `ym -1`을 각각 시험한 뒤 `xy 1 1`을 시험합니다.
6. 짧은 이동에서 `!` 정지와 기준 해제를 확인합니다. 다시 측정·등록한 후 반복성을 확인합니다.

기준 미등록 상태에서는:

```text
ERROR: XY NOT CALIBRATED. Use xyhelp and xycal
```

정상적인 `xm 1` 실행의 출력 형식은 다음과 같습니다. 펄스 수와 측정값은 자세에 따라 다릅니다.

```text
XY MOVE: 1.000 mm forward, 0.000 mm up
X COMMAND PULSE: <부호 있는 펄스 수>
Y COMMAND PULSE: <부호 있는 펄스 수>
XY DONE (encoder-derived): FORWARD <측정값> mm, UP <측정값> mm
XY ERROR: FORWARD <오차> mm, UP <오차> mm
```

문제가 생기면 A/B를 상대 관절각으로 입력하지 않았는지, SX/SY가 맞는지,
기존 `e`에서 양수 명령에 엔코더 변화가 양수인지, 두 모터가 각각 해당 링크의
절대각을 제어하는지 확인하세요. `ENCODER FOLLOWING ERROR`가 나오면 기준을
반복 입력해서 억지로 진행하지 말고 모터 전원, 엔코더 배선·부호와 걸림을 확인합니다.
정상 출력이어도 실제 방향이나 거리가 다르면 각도 측정과 링크/그리퍼 기하를 확인해야 합니다.

## 소프트웨어 검증

실물 없이 실행하는 기구학 및 모의 Arduino 테스트는 아래 명령으로 실행합니다.
이 결과는 실물 각도 보정, Mega 보드의 펄스 타이밍, 충돌 검증을 대신하지 않습니다.

```bash
g++ -std=c++11 -Wall -Wextra -Werror -pedantic tests/xy_motion_test.cpp -o /tmp/xy_motion_test
/tmp/xy_motion_test
g++ -std=c++11 -Wall -Wextra -Werror -pedantic tests/xy_control_test.cpp -o /tmp/xy_control_test
/tmp/xy_control_test
g++ -std=c++11 -Wall -Wextra -Werror -pedantic tests/z_homing_test.cpp -o /tmp/z_homing_test
/tmp/z_homing_test
```
